# TriComposer 创新点与娱乐科研价值分析

> 论文资料准备稿 ｜ 项目：TriComposer（dsh-rp-composer）｜ 2026-08-24

## 0. 一句话定位

TriComposer 把 AI 角色扮演的**输入侧**从"自由文本"改造为"结构化填空"，以交互设计手段解决长期依赖提示词工程约束的"台词/动作/心理成分混淆"问题。

## 1. 问题背景

在 LLM 驱动的互动叙事/角色扮演（RP）中，玩家的一条自然语言输入通常混合三类成分：

- **台词**（角色说出的话）——NPC 可听
- **动作**（角色的行为）——NPC 可见
- **心理**（内心想法）——原则上只有叙事者可见

纯文本输入没有机器可辨的成分边界，导致三类典型故障：

1. **越界知情**：NPC 对玩家"只是想、没有说"的内容做出回应，破坏信息边界与沉浸感
2. **成分误读**：动作描写被当作对话、内心独白被当成台词引用
3. **代理权侵蚀（抢话）**：模型替玩家补全未发生的言行

现有解法几乎全部押在**提示词侧**（在系统提示词里写"不要抢话""NPC 不得知晓玩家秘密"），属于对模型的软性约束，稳定性随模型、上下文长度、预设组合波动。SillyTavern 生态的"防抢话预设/正则"均属此类。

## 2. 创新点

### 2.1 输入侧结构化（核心创新）

将成分边界问题从"让模型读规则"转移到"让规则在输入产生时就存在"。三个填空框在 UI 层强制分离三种成分，组装模板（`【动作】“台词”（心理）`）输出**机器可解析**的消息。约束不再依赖模型自觉，而是由交互产物的格式保证。

对 RP 工具链而言，这是一个视角转换：主流 RP 前端（SillyTavern 及其衍生）的增强集中在输出侧（正则洗输出、面板渲染、世界书注入），输入侧长期只有一个裸文本框。TriComposer 证明了输入侧是低成本、高确定性的干预点。

### 2.2 "约定-解析-感知"闭环设计

插件不孤立存在，而是与提示词层的【输入解析协议】（Gent 预设）配套成闭环：

```
UI 填空（成分分离）
  → 模板组装（成分带标记）
    → 解析协议（模型按标记拆分）
      → 感知规则（NPC 只能听台词、看动作）
```

单独看每一环都是软约束或硬格式，组合后形成互相加固的两道防线：格式让机器"能分"，协议让模型"知道怎么分"。

### 2.3 零侵入的工程集成

- 使用宿主（DSH）的声明式槽位系统叠加 UI，不替换默认输入框，与其他 RP 插件（Agent RP、便携酒馆）共存
- 发送走标准草稿-提交管线，不引入私有消息通道，会话日志语义与人工输入完全一致
- 纯客户端、无构建步骤、约 170 行核心代码，可审计性高

### 2.4 填空式交互降低认知负荷

"用户做的只是填空"。字段标签自带语义提示（"心理 · NPC 不可见"），把需要记忆的标记语法转化为表单心智模型——对不熟悉 RP 标记约定的新手尤其友好，同时保留老手需要的详细视图（纵向多行）。

## 3. 娱乐价值

- **沉浸感保护**：心理活动不再"穿帮"，信息边界稳定，多周目长线 RP 的戏剧性（误会、隐瞒、试探）得以成立
- **门槛降低**：新手无需学习标记语法即可获得规范的输入格式
- **可组合性**：作为通用输入层，与任意预设/世界书/角色卡组合（已验证与"小图书馆"256 模块预设体系兼容）
- **社区生态位**：DSH 插件生态（dsh-plugin）中首个输入侧工具，与输出侧工具形成互补

## 4. 科研价值（写作角度建议）

### 4.1 可投方向

- HCI / 交互设计：structured input for mixed-modality user utterances in AI roleplay
- 互动叙事：player agency preservation（反抢话）作为可工程化指标
- 提示词工程实践：soft constraint（prompt rules）与 hard constraint（UI-enforced format）的可靠性对比

### 4.2 可做的实验设计（若要走实证路线）

- **对照实验**：同一 RP 脚本下，自由文本输入 vs 三段填空输入，统计"成分误识别率"（NPC 回应心理内容的次数 / 总轮数）、抢话次数
- **可用性测试**：新手完成指定 RP 任务的输入规范率、主观负担量表（NASA-TLX）
- **消融**：仅模板（无 UI 填空） vs 仅协议（无标记） vs 闭环，验证 2.2 的"两道防线互相加固"假设

### 4.3 诚实声明（局限性）

- 当前版本是工程贡献（tool/demo），尚无用户实验数据
- 效果依赖模型对标记约定的遵循度，弱模型上协议层仍可能失效
- 标记约定（【】“”（））是社区习惯方言，非标准格式

## 5. 相关工作

- SillyTavern 正则/预设体系：输出侧文本处理，无输入结构化
- DSH Agent RP：角色即顶层 Agent 的 RP 运行时，输入仍为裸文本框
- 各 RP 预设的"防抢话"模块：提示词软约束
- TriComposer 与上述均为互补而非替代关系
